## 🏗️ Project Vision: ColPackAgent

**Goal:** A multi-agent system for soft matter (HOOMD-blue) simulations that parameterizes and orchestrates robust, pre-written scientific workflows, scaling seamlessly from a local laptop to a multi-GPU cluster.

### 🌳 The Decoupled Architecture (Monorepo)

We are using a **Product Separation Pattern** combined with a **JSON-Driven Execution Model**. The codebase is split into three distinct domains: the core scientific engine, the CLI execution tools, and the pure agent prompts.

## 📅 The 5-Step Implementation Plan

### Step 1: Build the Independent Scientific Package (`src/colpack`)

**Goal:** Build a robust, human-usable scientific engine.

* **Action:** Develop the pure physics modules inside `src/colpack/` and configure `src/pyproject.toml`.
* **Key Innovation:** The `colpack.device.get_device()` HAL auto-detects hardware (CPU vs. GPU).
* **Developer Workflow:** Run `pip install -e src/` from the root directory to edit Python files and have changes instantly available.

### Step 2: Develop the CLI Tooling (`agent/tools`)

**Goal:** Create a safe, structured bridge between the LLM and the physics engine.

* **Action:** Write Python scripts (e.g., `init_sim.py`) that accept a JSON file as an argument (`--input setup.json`).
* **Function:** These scripts parse the LLM-generated JSON, validate the parameters, call the corresponding `colpack` library functions, and print clear success/failure logs to the terminal for the agent to read.

### Step 3: Establish the JSON-Driven Agent Knowledge Base (`agent/skills`)

**Goal:** Teach the LLM how to orchestrate the tools using strict JSON schemas.

* **The Master Skill:** `ColPackSkill.md` acts as the single point of entry, enforcing the sequential workflow and the **Working Directory Rule** (all work must happen inside a timestamped `data/` folder).
* **The Parametrization Pattern:** Sub-skills (e.g., `1_setup.md`) no longer ask the agent to write Python. Instead, they provide a strict JSON schema and tell the agent:
1. Generate `setup.json`.
2. Run `python ../../agent/tools/init_sim.py --input setup.json`.
3. Verify the terminal output before proceeding.



### Step 4: Distribution & Publishing

**Goal:** Make the backend package available to human scientists and external AI agents.

* **For Early Dev / Agents (GitHub):** `pip install "colpack @ git+https://github.com/YOUR_USERNAME/ColPackAgent.git#subdirectory=src"`
* **For Stable Release (PyPI):**
Navigate to `/src`, build the wheels (`python3 -m build`), and publish (`python3 -m twine upload dist/*`).

### Step 5: Standalone Application Wrapper (`agent/sdk_app`)

**Goal:** Evolve beyond standard UI chats into a fully autonomous, programmable agent.

* **Action:** Build `colpack_runner.py` using an Agent SDK framework. This wrapper initializes the LLM, loads the `ColPackSkill.md` orchestrator, and provides the terminal execution tools required to run full parameter sweeps automatically.

---

### ✅ Success Criteria for V1

1. **High Reliability:** By forcing the LLM to output JSON rather than Python, syntax errors and unphysical logic loops are virtually eliminated.
2. **Clear Fault Isolation:** If a run fails, the bug is instantly traceable. Bad parameters = LLM error (check the `.json`). Code crash = Python error (check `agent/tools/` or `src/colpack/`).
3. **True Decoupling:** The scientific package, the CLI tools, and the agent prompts remain completely separated and maintainable.
